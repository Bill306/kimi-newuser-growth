AI 产品经理作业 · 2026 年 11 月

Kimi 新用户 7 日会员转化方案

目标：提升注册 7 天内用户的会员转化率，同时 D7 留存不能下降。

核心判断：新用户 7 天里有两个决定性时刻。注册后的头几分钟，要让用户不用想、不用打字就做成一件和自己有关的事（Aha）；额度用完的那一刻，要先帮用户做一部分再推付费，并留一条免费退路。前一个时刻决定有多少人走到后一个时刻，所以先做 Aha（P0），再接住撞墙（P1）。

最大流失点：③ 首问 → ④ 激活

大多数用户只问一个问题，从没碰到深度研究、PPT 这些 Kimi 真正领先的能力。这些用户后面不会撞墙，也就不会进入付费漏斗。走查还发现，在这之前游客连第一个回答都要先登录才能拿到（② 节点），所以「问一个就走」的一部分其实是「没登录就走」。

最大转化杠杆：⑥ 撞墙

用户带着有截止时间的任务来、额度不够，是 7 天内付费意愿最高的时刻。现在的处理方式（新任务直接提示额度不足）同时浪费了转化，还伤留存。

竞品怎么处理同一时刻

产品新用户引导撞墙时的处理可借鉴
ChatGPT已核实 游客可以直接在输入框提问，左侧常驻「登录后可以基于历史对话回答、生成图片、上传文件」的说明，右上角是「Sign up for free」待核实 免费额度用完后降级到小模型继续回答，并显示恢复时间和升级入口登录提示讲「登录后多得到什么」；撞墙时降级而不阻断
Perplexity待核实 推荐问题、Discover 信息流待核实 每天给少量 Pro Search，用完后回到普通搜索先让免费用户尝到高级能力
豆包已核实（仅香港网络） 未登录访问被提示「受区域限制，请先登录再使用」，并引导到海外版 Dola待核实 基本不设付费墙内地网络下的游客流程需另行走查

04三个需求与优先级

P0

需求 A：注册后直达 Aha

旅程节点
② 登录 → ③ 首问 → ④ 激活
问题
新用户不知道 Kimi 能做什么，也想不出该让它做什么，只好先问一个普通问题；回答和普通聊天机器人差不多，问完就走。灵感库里的案例是别人的，用户还要自己改写成自己的需求。
方案
  • 2 个点选问题：注册成功后问「你主要用 Kimi 做哪方面的事」「最近想搞定什么（最多选 3 个）」。不打字，约 10 秒，可以跳过
  • 专属任务预填进输入框：例如投研用户 + 研究 →「帮我做一份深度研究：宁德时代和比亚迪的储能业务谁更有竞争力？……」，用户只需按发送或 Enter
  • 可以换、可以改：输入框上方再给两个推荐，一键切换；上方卡片说清楚要多久、会得到什么
  • 首个 Agent 任务免费、不占额度，保证第一次体验不撞墙
  • 成果后给下一步（「把它做成 PPT」「每周一更新」），成果保存在首页，留下回来的理由
  • 兜底：跳过引导的用户，首问回答后按意图推荐一个能一键执行的 Agent 能力
影响指标
引导完成率、预填发送率 → D0 Aha 达成率、Agent 渗透率 ↑ → D1 / D7 留存 ↑ → 触顶率 ↑ → 7 日转化率 ↑
验证
A/B，3 组（见第 05 节）。先看引导完成率、预填发送率、D0 Aha 达成率和 D1 留存（1–2 天可读），再看 7 日转化和 D7。推荐任务与回答的匹配度单独抽样人工评估。
P1

需求 B：额度触顶时的「任务续航」付费引导

旅程节点
⑥ 撞墙 → ⑦ 收银台
问题
用户发起重要任务时，额度不足会直接拦下新任务：不说要多少、不先给任何成果、只给一张通用会员页、不付费就没有出路。
方案
  • 动手前预估：发任务时显示「这个任务约需 30%，你还剩 12%」，把百分比翻译成「能做几页 / 几份」
  • 先免费交付一部分：用剩余额度做出大纲和前几页，并自动保存
  • 按任务推荐一个档位：标题写「还差 9 页就完成了」，只推 Go，附新人首月价，有效期和注册 7 天窗口绑定
  • 两条免费退路：额度刷新时提醒继续；用普通对话先给文字版
  • 付费后无缝续写，不用用户重新发起
影响指标
曝光→点击率、点击→支付率 ↑ → 7 日转化率 ↑；触顶后空手离开率 ↓ → D7 留存持平或上升
验证
注册时按用户 ID 随机分组，跑满 2 个完整的 7 日 cohort。主分析看全体新用户（ITT），同时看「触顶用户」子集。D7 做非劣效检验。新人首月价单独开一个因子（¥19.9 / ¥29.9 / 无折扣）。和需求 A 的实验正交分层，可以同时运行。
P2

需求 C：会员页按使用情况推荐档位

旅程节点
⑦ 收银台
问题
五档会员、按功能列权益，新用户算不清自己需要哪一档，在选档时犹豫流失。
方案
根据用户 7 天内的使用情况默认选中一个档位（「你这周做了 3 次深度研究、1 份 PPT，Go 够用」）；权益从功能清单改写成「每月大约能做多少件事」；默认只展开 Go 和 Plus，其余折叠。注册时的职业和兴趣回答（需求 A）也可以作为推荐依据。
影响指标
收银台下单率、支付成功率 ↑；ARPPU 可能下降，需要同时监控
验证
A/B。主指标是收银台转化率，同时看 ARPPU 和首月后升档率，确认没有把本来会买 Plus 的人推到 Go。

为什么这样排

需求离钱的距离作用人群留存风险研发成本多快能读出结果
A 注册后直达 Aha远：转化的上游全部新用户正向：直接拉高 D1 / D7中：两个问题 + 预填模板 + 首任务赠送先行指标 1–2 天；转化 7 天
B 任务续航最近：直接作用于付费意愿最高的时刻触顶用户（规模取决于免费额度和 A 的效果）低：有免费退路，且只影响已经撞墙的人中：要做消耗预估和部分交付快：7 日 cohort
C 档位推荐近：只在漏斗最后一段最少：已进入收银台的人极低低快

A 排第一：它作用在最大的流失点、覆盖全部新用户，而且是唯一同时推高转化和留存的需求，正好对应「转化提升、留存不降」这道题。B 排第二：离钱最近，但只对撞墙的人有效；A 把更多人带到撞墙这一步，B 再把他们接住变成付费，两者是接力。C 排第三：改动小，可以和 B 并行，但作用人群最少。

反方最强的反驳

A 离付费远、链路长，7 天内未必能变成付费；首个任务免费还可能推迟撞墙。B 离钱最近，7 天内就能直接读出转化。

我目前的立场

仍然 A 第一：走查看到的最大问题是新用户根本没碰到 Agent 能力，B 能作用的人群取决于 A；A 的先行指标 1–2 天就能读出；首任务只免费一次，对撞墙时间的影响在实验里单独测。改变排序的条件：如果埋点显示 7 日触顶率已超过 30% 假设阈值，说明上游不缺人，B 提到第一。

05需求 A 的实验设计

假设

注册后用 2 个点选问题生成并预填一个专属任务，能让 D0 Aha 达成率明显上升，7 日转化率相对提升 ≥15%，且 D7 留存不下降。

分组

  • 注册时按用户 ID 哈希分 3 组，跨端一致
  • 对照组（现状）／ 引导 + 预填／ 引导 + 预填 + 首任务免费
  • 把「引导设计」和「赠送额度」的效果分开测
  • 主口径 ITT：跳过引导的人也算实验组

样本量与读数节奏

假设 7 日转化基线 2.0% 假设，检测相对 +15%（到 2.3%），α=0.05、功效 80%：每组约 3.7 万名新用户。第 1–2 天读引导完成率、预填发送率、D0 Aha、D1；满 7 天读转化和 D7。

停止 / 回滚条件

  • 注册后首个动作率降幅 >3pp（引导页本身造成流失）
  • D1 留存降幅 >1pp，立即暂停
  • 推荐任务被人工评为「不相关」的比例过高

需求 B 的实验和 A 正交分层：两者作用在不同节点，可以同时跑，分析时检查交互效应。

06原型

题目要求针对一个需求做原型，这里选 P0 需求 A「注册后直达 Aha」。原型用一个手机界面模拟新用户注册当天的过程，可以在实验组和对照组之间切换，右侧实时显示埋点事件和本次会话的漏斗。

建议体验路径
  • 选一个职业和 1–3 件想做的事 → 点「帮我准备第一个任务」→ 输入框里出现专属任务，按发送或 Enter → 打开成果，漏斗走到「Aha」
  • 点「换一个身份再试一次」，看不同职业的预填任务和成果怎么变
  • 在引导页点「跳过」，看兜底的能力推荐卡
  • 切到对照组：空白首页 → 问一个普通问题 → 问完就走

07反方观点

判断最强的反驳我目前的立场
注册后先问问题能带来 Aha多一个步骤就多一处流失，有人会直接关掉全部点选、约 10 秒、可以跳过；「注册后首个动作率」作为护栏，降幅超过 3pp 就停
预填任务比灵感库更有效两个问题信息量太少，推荐可能和真实需求不符，反而显得不懂用户给 3 个推荐可换、可改；记录「换过」「改过」的比例，持续调整推荐
首个任务免费能保护第一次体验白送额度会推迟撞墙、减少 7 天内付费，也有算力成本实验单独设一组不赠送，把赠送的效果分开测；成本纳入护栏
触顶时推付费有效（需求 B）如果免费额度很大，大部分新用户 7 天内撞不到墙，B 作用的人群太小先查「7 日触顶率」；需求 A 会提高触顶率，两者一起看
动手前预估消耗能减少挫败感把成本摆在眼前，可能让用户不敢用 Agent 能力，降低渗透率只在剩余额度不够这个任务时显示预估，平时只显示常驻额度条；把「Agent 渗透率」加进监控
新人首月价能拉高转化折扣拉来的是低意愿用户，次月续费差，长期收入可能变少价格单独做一个实验因子，以「首月 + 次月」的累计收入为准做决定
免费退路能保护留存给了退路，部分本来会付费的人选择等待，转化被稀释这是有意的取舍，留存是底线。可以看「提醒 → 回访 → 二次触顶 → 付费」这条延迟转化链路，它会把一部分转化拉回来

最难、最容易出错的部分

需求 A：两个问题的选项设计和预填任务的匹配度，决定用户是「被说中了」还是「被打扰了」，只能靠实验和人工抽样评估验证。需求 B：免费额度在第几天让新用户撞墙、新人价给多少，直接决定转化提升和留存损失之间的取舍；消耗预估如果不准（说还差 18%，实际差 40%），会直接损害信任。
